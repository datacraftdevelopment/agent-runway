# Count words and lines

Chunk: practice · Risk: low: a new standalone module and CLI in a practice repo; nothing else uses it · Map: none

## Problem Statement

Someone testing a pm-runway setup needs a chunk small enough to finish in minutes, with a real
blocking edge and two tickets that can run at once on different machines.

## Solution

`tally` counts words and lines in text, as functions and from the command line.

## User Stories

1. As a user, I want the number of words in a piece of text, so that I can size it.
2. As a user, I want the number of lines in a piece of text, so that I can size it.
3. As a user, I want `python3 -m tally <file>` to print both counts, so that I don't write code.

## Implementation Decisions

- `tally.words.count_words(text) -> int`: words are runs of non-whitespace.
- `tally.lines.count_lines(text) -> int`: a final line without a newline still counts; empty text is 0.
- `python3 -m tally <file>` prints `words: N` and `lines: N` on two lines; a missing file exits 2 with a message on stderr.

## Testing Decisions

- Test only through the public functions and the CLI's output and exit code.
- Seams: `count_words`, `count_lines`, and the CLI run as a subprocess.
- Prior art: `tests/test_smoke.py`.

## Acceptance

- [ ] A1: `count_words("a b  c")` is 3 and `count_lines("x\ny")` is 2. Verify: `python3 -m unittest -q`
- [ ] A2: `python3 -m tally README.md` prints a words line and a lines line and exits 0. Verify: run it
- [ ] A3: `python3 -m tally nope.txt` exits 2. Verify: run it, then `echo $?`

## Out of Scope

Characters, bytes, encodings, globbing several files.
