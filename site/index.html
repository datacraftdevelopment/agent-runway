Agent Runway

A ready-made software factory for one.

You don't have to build your own factory. Install Runway and keep working in Claude Code or Codex the way you do now. When part of the job can run on its own, file it as a ticket. Runway runs it on your Mac, has a fresh session review it, and only merges what is low risk.

Download for Mac Source on GitHub

Early preview, version 0.1.1. Signed and notarised by Apple, and it updates itself. Open the disk image, drag Runway to Applications and open it. macOS 14 or later. See how it works.

How it works

You decide what to build. Runway builds it.

The thinking stays with you, in a normal Claude Code or Codex session. Once the work is shaped into tickets and you type go, everything after that runs without you. You only come back for a merge that isn't low risk.

  1. You + your agent

    Discover

    Talk the problem through. For big, foggy work, map out the decisions first.

    wayfinder · grill-me
  2. You + your agent

    Prototype

    Answer a design question with a throwaway prototype before anything real is built.

    prototype
  3. You + your agent

    Spec

    Turn the conversation into a spec: what done looks like, and how to check it.

    to-spec
  4. You type go

    Tickets

    Your agent breaks the spec into small tickets, each with its risk and acceptance checks. Nothing is filed until you say go.

    file-tickets
  5. Runs on its own

    Build and check

    Each ticket runs on a free Mac in its own worktree. Then two fresh sessions review it: one reads the code, and one runs every acceptance check.

    Runway app
  6. Runs on its own

    Merge

    Low-risk work that passes review and checks merges itself. Anything else waits on your board as one question.

    runway

If a ticket gets stuck, copy its take-back prompt from the board and finish it with your agent. Then give it back to Runway, mark it done, or drop it.

Every skill in the workflow, and what each one does →

One subscription is enough

Tickets run with the Claude Code or the Codex you already sign in to. You don't need both, any API keys, or a service in between.

Nothing hosted

One SQLite file on your Mac holds every ticket and run. Specs and code stay in your git repos.

Nothing hidden

The loop runs only while the app is open. No daemons, no launch agents. Close the app and dispatch pauses; runs already started finish.

A gate you can read

Auto-merge needs low risk, a passing review on the exact commit, green checks, and no sensitive paths such as auth, payments, migrations or CI. A reviewer can raise risk, never lower it.

Claude Codex Any

Use whichever one you have. With both, pin a ticket to one agent or let whichever is free take it, and when one hits its usage limit the next tickets go to the other.

Many Macs, one board

Each repo has a main computer, and a ticket can be pinned to the Mac where its files live. The board shows what runs where.

Know how hands-off it is

A strip on the board shows how many tickets merged without you, how long they took, what they cost, and where the others stopped.

It learns from its stops

When three tickets stop for the same reason in a week, Runway files a retro ticket to fix the cause. Its pull request links every failed run, and it never merges itself.

Questions

What people ask first

What does it cost?

Nothing extra. Runway is free, and tickets run on the subscription you already have: Claude Code or Codex, even an entry-level plan. There are no API keys and nothing is billed per run.

Do I need both Claude Code and Codex?

No. Runway works with just one. Every ticket gets two fresh-session reviews, one of the code and one of the acceptance checks, and with one agent both run on it. If you have both, the code review goes to the other agent, which catches a bit more.

Does my code leave my Macs?

Runway itself sends nothing anywhere. Tickets and runs live in one SQLite file on your Mac. Your code goes where it already goes: to GitHub, and to Claude Code and Codex as they work on it.

What stops it merging something bad?

A gate written in code, not a prompt. A ticket merges on its own only when it was marked low risk while it was shaped, both fresh reviews (code and acceptance checks) passed on the exact commit, the checks are green, and it touches no sensitive paths such as auth, payments, migrations or CI. A reviewer can raise the risk but never lower it. Everything else waits for you.

Is this for teams?

No. Runway is for one developer working across their own repos and Macs. There's no Slack bot, no shared cloud and no seats. If you want a hosted factory for a whole engineering team, cloud products such as Warp Factories are built for that.

Do I have to design my own workflow?

No. Runway comes with one: discover, prototype, spec, tickets, then hands-off build, review and merge. Install it and use it as it is. Every skill it uses comes with the app. The shaping steps are inspired by Matt Pocock's open skills, so it's a tried way of working, not one invented for Runway. If you already work another way, file-tickets can file tickets from any session.

What if I hit my usage limit?

Runway rests that agent until the limit resets, and the ticket goes back in the queue without using up its fix attempt. If you have both agents, the next tickets go to the other one in the meantime.
