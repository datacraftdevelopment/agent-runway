Agent Runway

Keep working with Claude Code and Codex the way you do now. When part of the job can run on its own, file it as a ticket. Runway runs it on your own Macs, has the other agent review it, and only merges what is low risk.

How it works

From a normal session to a merged pull request

  1. Work as you do now

    Talk to Claude Code or Codex in your repo. Shape the work there, as much as it needs.

  2. Say go

    When part of it can run unattended, the agent proposes a short batch of tickets: what done looks like, the risk, what it touches. Nothing is filed until you type go.

  3. It runs

    Each ticket goes to a free runner: this Mac, another of your Macs over SSH, or the cloud, in its own git worktree.

  4. The other agent checks it

    A Claude Code ticket is reviewed by Codex and the other way round. Low-risk work merges on its own. Everything else waits on your board with its pull request.

Your own subscriptions

Tickets run with the Claude Code and Codex you already sign in to. No API keys to buy, no service in between.

Nothing hosted

One SQLite file on your Mac holds every ticket and run. Specs and code stay in your git repos.

Nothing hidden

The loop runs only while the app is open. No daemons, no launch agents. Close the app and dispatch pauses; runs already started finish.

A gate you can read

Auto-merge needs low risk, a passing review on the exact commit, green checks, and no sensitive paths such as auth, payments, migrations or CI. A reviewer can raise risk, never lower it.

Claude Codex Any

Pin a ticket to one agent or let whichever is free take it. When one hits its usage limit, the next tickets go to the other until it resets.

Many Macs, one board

Each repo has a main computer, and a ticket can be pinned to the Mac where its files live. The board shows what runs where.
