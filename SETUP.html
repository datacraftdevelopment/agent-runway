pm-runway · setup

Set up your Macs to build while you're away

You shape the work. Your Macs build it, review it with a second model, and land it. This is the short version for you. Hand SETUP-AGENT.md to Claude Code and it does the typing; you do the parts that need your hands.

The controllerOne Mac that's usually awake. Runs Orca, the loop and the board. Builds too.
WorkersYour other Macs. They run Orca and build or review whatever the loop sends them.

  1. Basics on every Mac agent

    Apple's command line tools, Homebrew, and the GitHub CLI. You sign in to GitHub once when asked.

    Every Mac

  2. Claude Code and Codex you sign in

    The command-line versions of both, not the desktop apps. You sign in to each with your own subscription: /login in Claude, codex login for Codex. Nothing else pays for the work.

    Every Mac

  3. Tailscale you sign in

    Puts your Macs on one private network so they can reach each other from anywhere. Use the same account on every Mac.

    Every Mac

  4. Orca agent

    The app where all the sessions run. When it first opens, let it read your home folder and import your Claude and Codex settings.

    Every Mac

  5. The pm-runway plugin agent

    One plugin with the whole workflow. If pm-sp or pm is installed, you uninstall it first; the agent tells you the command.

    Every Mac

  6. Pair the Macs in Orca you click

    On each worker: Settings, Remote Orca Servers, New Link, then copy it. On the controller: Add Server, give it the worker's name, paste. Treat that link like a password.

    Controller and each worker

  7. Your repo, everywhere agent

    The agent clones it on each Mac, adds it in Orca, and commits a small runway.json that names your test command.

    Every Mac

  8. Tell the controller about the Macs agent

    A short list of your Macs and how many tickets each may build at once. It stays on the controller, never in a repo.

    Controller

  9. Run the practice chunk you watch

    A tiny practice repo with three tickets. Two should start at once on different Macs, the third after both land, then the whole thing merges to main on its own. In Orca, open a terminal tab and run runway loop --chunk practice, and open the board in a browser tab beside it.

    Controller

Every day after that

  • Shape a chunk with Claude: talk it through, to-spec, to-tickets, and say go.
  • runway start, then runway loop in an Orca tab. Walk away.
  • The board shows Queued, Implementing, In review, Merged and Waiting on you. Orca flags any session that needs you.
  • Ask a Claude session "what's happening with this ticket?" any time. runway pause stops new work from starting.
Keep the controller and any busy worker awake and online while work runs. Everything else is in SETUP-AGENT.md.
